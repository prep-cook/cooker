Changed

- `POST /v1/alpha/search` and `/backend-api/codex/alpha/search` fail over to the next eligible Codex credential when the upstream refuses a search, instead of returning the upstream's status and body. The client gets the search result JSON as `application/json`, with the members the upstream sent; the response carries `X-Ck-Stream-Id` and resumes with `GET /v1/streams?after=v1.b.<bytes>`.
- A search body that is not a JSON object with a string `query`, or that repeats a member, is refused with 400 before anything is sent; a body over 16 MiB is refused with 413 instead of being cut. Errors use the OpenAI error shape (`{"error":{"message":…,"type":…}}`) instead of `{"error":"…"}`.
- A Codex API key with `alpha-search: true` but no base URL is no longer selected for Alpha Search.
- Every video route is served on the execution contract. Job bodies (`POST /v1/videos*`, `GET /v1/videos/{id}`, `POST /openai/v1/videos`, `GET /openai/v1/videos/{id}`) are `application/json` with `Cache-Control: no-store` and `X-Ck-Stream-Id`, without `Content-Length` or a leading keepalive newline, and resume with `GET /v1/streams?after=v1.b.<bytes>`. OpenAI-shaped bodies list `id`, `object` and `status` first; their members are unchanged except as below.
- `GET /openai/v1/videos/{id}` reports xAI's `expired` and `cancelled` as such instead of `failed`, and a failed job's `error` is xAI's own `{"code","message"}` object without an added `progress: 0`. `GET /v1/videos/{id}` reports a queued job as `pending`, xAI's documented word.
- `GET /openai/v1/videos/{id}/content` streams the file from its first byte with the host's media type, `Cache-Control: no-store` and `X-Ck-Stream-Id`, and resumes from a byte cursor; the host's `Content-Length`, `Content-Disposition`, `ETag` and `Last-Modified` are no longer relayed. The poll it makes charges the job's usage when no earlier poll did.
- A video create whose answer names no job fails over to the next eligible credential before anything is sent to the client, instead of answering 502 at once.
- `POST /v1/videos/edits` and `/extensions` refuse options xAI does not document for them (for example `duration` on an edit) with 400 before anything is sent; the body's members reach xAI in a fixed order.
